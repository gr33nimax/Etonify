# HydraBox 2.0 — целевая продуктовая архитектура и UX-ревью

Артефакт задачи `H2-UX01` (§6, фаза E2). Проводит тимлид с владельцем; исполнителю не
выдаётся как задача — из него выдаётся `H2-E08` и амендменты.

Нормативный принцип этого документа: **1.x — источник возможностей, но не источник
UX.** Экран 2.0 проектируется от пользовательской задачи, а не от внутренней сущности.
Инвентарь экранов из §6 фазы E ниже пересматривается решением тимлида — это
предусмотренный планом путь («Экран, которого в нём нет, в 2.0 не появляется без
решения тимлида»), а не отклонение от плана.

## 1. Пользовательский словарь (закрыт)

Одно понятие — одно слово. Слева то, что видит пользователь; справа — что запрещено в
основном UI.

| Пользовательское понятие | Запрещённые синонимы в основном UI |
|---|---|
| **Подписка** — источник серверов | профиль, profile, source, каталог |
| **Сервер** — один выбираемый узел | прокси, proxy, outbound, node, tag, эндпоинт |
| **Авто** — сервер выбирается по скорости | urltest, selector, automatic outbound |
| **Подключение** / Подключено / Подключаюсь | туннель, runtime, tun, сессия |
| **Приложения вне VPN** | split routing, split tunnel, exclude_package |
| **Правила** — что идёт в VPN, что напрямую | routing, route, rule-set, geoip |
| **Диагностика** | logs, snapshot, evidence |

Запрещены в основном UI полностью, разрешены только в Диагностике: `READY`,
`STARTING`, `RECOVERING`, `generation`, `lanes`, `transport`, `snapshot`, `outbound`,
`MTU`, `inbound`, `selector`, коды ошибок, имена исключений.

## 2. Целевая информационная архитектура

Три destination вместо пяти. Навигация — по задачам: «пользоваться», «выбрать куда»,
«настроить». Диагностика и подписки перестают быть разделами верхнего уровня, потому
что это не ежедневные задачи.

```
Дом                     — подключён ли я, куда, что нажать
  └ Трафик (деталь)     — открывается тапом по скорости, не таб
Серверы                 — Авто + список, поиск, задержка, группы по подписке
  └ Подписки (деталь)   — управление источниками из тулбара Серверов
      └ Добавить        — ссылка / буфер / QR / файл
      └ Детали подписки — срок, число серверов, обновить, переименовать, удалить
Настройки               — базовые
  └ Приложения вне VPN
  └ Правила
  └ Внешний вид (тема, язык)
  └ О программе (версия, что нового, условия, политика)
  └ Диагностика (логи, экспорт, уровень)
  └ Для продвинутых (свёрнуто, с предупреждением)
        DNS-резолверы · MTU · TLS-фрагментация · параметры проверки скорости ·
        режим производительности · лимит памяти · локальный прокси-порт ·
        резервная копия и импорт · сброс настроек
Онбординг (блокирующий, один раз, вне навигации)
  Приветствие → Условия → Добавить подписку → Разрешение VPN → Первое подключение
```

Решения по инвентарю:

- **удалено:** таб «Логи», таб «Подписки», карточка «Route» на Доме, постоянный баннер
  условий, экран `settings_urltest_page` (уже исключён планом), отдельный экран
  «шаринг прокси» (действие в контекстном меню сервера, не экран);
- **объединено:** подписки внутрь Серверов; трафик — деталь Дома, не раздел;
  changelog внутрь «О программе» (совпадает с планом);
- **добавлено:** онбординг (в 1.x есть `features/welcome`, в 2.0 отсутствует),
  раздел «Для продвинутых», продуктовые состояния отказа;
- **переименовано:** по таблице §1.

## 3. User journeys с бюджетом шагов

Бюджет — критерий приёмки, а не пожелание. Проверяется на устройстве.

| Задача | Целевой путь | Бюджет |
|---|---|---|
| Установка → идёт трафик | онбординг: Далее → Принять → вставить ссылку → Добавить → Разрешить VPN → Подключиться | ≤ 6 нажатий, 0 «непонятных» экранов |
| Повторное подключение | Дом → главный контрол | 1 |
| Сменить сервер | Дом → чип сервера → тап по серверу (переподключение само, без ручного Disconnect) | 3 |
| Понять, почему не работает | причина и действие уже на Доме | 0 переходов |
| Ограничить набор приложений | Настройки → Приложения вне VPN → тумблеры → «Переподключить сейчас» | 3 + N |
| Обновить подписку | Серверы → Подписки → Обновить (или автоматически по расписанию) | 3 |
| Роуминг / потеря сети | состояние «Переподключаюсь», восстановление само, ошибки не показывать | 0 |
| Диагностика проблемы | Настройки → Диагностика → Экспорт | 3 |

## 4. Состояния как UX, а не как поля

### Дом отвечает ровно на три вопроса
Защищён ли я сейчас · через какой сервер · что я могу нажать. Всё остальное на Доме
лишнее.

Состав: большой главный контрол подключения (единственный акцент экрана), под ним
строка состояния человеческим языком, под ней один чип сервера, при подключении —
время сессии и две цифры скорости (тап → Трафик). Индикатор режима показывается
только когда режим не по умолчанию.

### Состояния Дома (проектируются как отдельные экраны состояния)

| Состояние | Что видит пользователь | Единственное действие |
|---|---|---|
| Нет подписки (первый запуск) | один цельный экран: что такое HydraBox, что нужно сделать | «Добавить подписку» (+ «Вставить из буфера») |
| Подписка есть, серверов нет | «В подписке нет серверов» | «Обновить подписку» |
| Готов | «Не подключено» + чип сервера | «Подключиться» |
| Подключаюсь | прогресс внутри контрола, без фаз рантайма | «Отменить» |
| Подключено | «Подключено» + сервер + время + скорость | «Отключиться» |
| Переподключаюсь (сеть сменилась) | «Переподключаюсь…» — это не ошибка | ничего (или «Отменить») |
| Отключаюсь | «Отключаюсь…» | ничего |
| Нет интернета | «Нет подключения к интернету» | «Повторить» |
| Сервер не отвечает | «Сервер <имя> не отвечает» | «Выбрать другой» / «Авто» |
| Подписка истекла или недоступна | «Подписка недоступна» | «Обновить подписку» |
| Конфигурация неверна | «Не удалось подготовить подключение» | «Повторить» + «Диагностика» |
| Разрешение VPN отклонено | «Нужно разрешение системы» | «Разрешить» |

Правило: **одна причина — один экран состояния — одно действие.** Ни одно состояние не
показывает две проблемы одновременно и не выводит код ошибки.

### Прочие экраны
Каждый экран инвентаря обязан иметь спроектированные «пусто / загрузка / ошибка /
частичный успех». Пример частичного успеха: подписка обновилась, но три сервера
исчезли — показать «обновлено, 3 сервера удалены», а не молчаливую подмену списка.

Опасные действия: удаление подписки — подтверждение с указанием, что серверы исчезнут
и активное подключение прервётся; импорт резервной копии — подтверждение перезаписи;
смена режима или списка приложений при активном туннеле — предупреждение «применится
после переподключения» с кнопкой переподключить.

## 5. Material 3 Expressive — что именно требуется

Не «MaterialTheme + Card + Button». Обязательно:

- главный контрол подключения как выразительный крупный элемент (морфинг формы по
  состоянию, пружинная моция, тактильный отклик), а не `Button` в карточке;
- типографическая иерархия: display/headline для состояния, body/label для деталей;
  сейчас весь экран — `bodyMedium`/`titleMedium`;
- тональные поверхности и осмысленные контейнеры вместо одинаковых
  `surfaceContainerLow`-карточек подряд;
- единый shape language: разные роли — разные радиусы из девяти токенов;
- `TopAppBar` (large → small при скролле) вместо `Text` в начале скролла;
- навигация с иконками (сейчас `icon = {}` — навбар без иконок, нарушение MD3 и
  доступности), badge на Серверах при проблеме с подпиской;
- переходы между состояниями подключения — анимация одного контрола, а не подмена
  карточек; общая ось motion для перехода Дом → Серверы;
- edge-to-edge (`enableEdgeToEdge`, WindowInsets) — сейчас отсутствует полностью;
- dynamic color уже есть; проверить контраст в обеих темах и три уровня контраста;
- доступность: цели ≥ 48 dp, contentDescription для главного контрола и статуса,
  озвучивание смены состояния через `liveRegion`, уважение к уменьшенной анимации.

Ограничение: моция и выразительность применяются к главному контролу, переходам
состояний и навигации. Списки серверов и настройки остаются спокойными.

## 6. Findings по текущей реализации

Оси — по `H2-UX01`. Важность: **BLOCKER** (без правки продукт нельзя показывать),
**MAJOR**, **MINOR**. Ссылки — на код на момент `f01c0a9`.

### Ось 1–2: задачи и первый запуск
- **F-01 BLOCKER. Первого запуска нет вообще.** Онбординга нет; вместо него на всех
  пяти табах висит секция «Before you start» (`HydraApp.kt:78`, `:110`), потому что
  правовое согласие вставлено выше `when(destination)`. Путь «установил → идёт трафик»
  требует самостоятельно догадаться: принять условия → уйти в таб «Subscriptions» →
  понять, что вставлять в поле про `#hydra-key` и sing-box-документ → вернуться →
  выбрать сервер → подключиться. Это ≥ 9 шагов и три перехода табов против бюджета 6
  без переходов. В 1.x онбординг есть (`lib/features/welcome`, `legal_consent_page`
  371 строка) — не перенесён.
- **F-02 BLOCKER. Дом не отвечает ни на один из трёх вопросов однозначно.** При пустом
  состоянии он показывает пять следствий одного факта: «Disconnected», «No server
  selected» (`:136`), «Pick a server / 0 available» (`:158`), «No subscription yet»
  (`:162`), выключенный Connect. Нужен один экран состояния с одним CTA.
- **F-03 MAJOR. Смена сервера — не задача, а обход интерфейса.** Список серверов —
  отдельный таб, выбор не предлагает переподключения; «Measure now» доступен только
  при активном туннеле (`ProxiesScreen`, `primaryEnabled = state.canStop`) и назван
  инженерным термином.

### Ось 3: неоднозначность настроек
- **F-04 MAJOR. Настройки — плоский список технических полей.** DNS-резолверы, MTU и
  список приложений лежат на первом уровне рядом с «Status notification». Ни у одной
  настройки нет пояснения следствия; ни одна не предупреждает, что применится только
  после переподключения (а MTU, DNS и список приложений применяются именно так).
- **F-05 MAJOR. «Performance mode» показан как read-only строка `standard`**
  (`HydraApp.kt:314`) — настройка, которую нельзя изменить и чьё следствие не описано.
- **F-06 MINOR. Разделения на базовые и продвинутые нет.** MTU и резолверы обязан
  видеть каждый пользователь.

### Ось 4: обратная связь об отказе
- **F-07 BLOCKER. Причины отказа не различаются.** На Доме в одну строку выводится
  `errorCode` рантайма (`HydraApp.kt:136`, `ScreenProjection.kt:133`) — например
  `CONFIG_INVALID`. «Нет сети», «сервер не отвечает», «подписка истекла», «конфиг
  неверен» неотличимы, действие не предлагается.
- **F-08 BLOCKER. Пользователю показываются тексты исключений.** `"Failed: ${it.message
  ?: it::class.simpleName}"` (`RuntimeControlActivity.kt:171`, `:204`) — в баннере может
  оказаться `Failed: NullPointerException`. Плюс баннер распознаёт свой тип по
  `text.startsWith("Failed")` (`HydraApp.kt:88`), то есть тип ошибки закодирован в
  строке.
- **F-09 MAJOR. Восстановление после потери сети выглядит как подключение.**
  `RECOVERING` и `STARTING` проецируются в один `CONNECTING` без различия в тексте;
  пользователь не понимает, что происходит переподключение, а не его действие.

### Ось 5: опасные и необратимые действия
- **F-10 MAJOR. Удаление подписки без подтверждения** — кнопка «Remove» в раскрытой
  карточке рядом с «Rename» и «Refresh», одним нажатием, вместе с активным
  подключением через её сервер.
- **F-11 MINOR. Переключение приложений вне туннеля при активном подключении** ничего
  не сообщает: настройка сохранена, туннель работает по старому списку.

### Ось 6: состояния экранов
- **F-12 MAJOR. Пустые состояния — текстовые заглушки.** «Nothing stored yet» с
  абзацем про `https://`, `#hydra-key`, sing-box-документ и `vless / trojan / ss /
  socks` — это документация формата в пустом состоянии. «No servers · Add a
  subscription first» — тупик без действия.
- **F-13 MAJOR. Загрузка — одна `LinearProgressIndicator` над всем экраном**
  (`HydraApp.kt:76`), и `busy` поднимается только на операциях подписки и бэкапа;
  подключение и обновление списка серверов происходят без индикации.
- **F-14 MAJOR. Частичный успех не существует как состояние.** Результат операции
  показывается строкой «Last operation: done | in progress | <код ошибки>».

### Ось 7: избыточная сложность
- **F-15 MAJOR. Таб «Logs» в основной навигации** — пятый из пяти разделов отдан
  диагностике, которая ежедневному пользователю не нужна ни разу.
- **F-16 MINOR. Отладочные строки в продуктовом UI:** «Backup — versioned schema,
  export arrives with the next task» (`:390`), «Log level — unknown» (`:399`),
  «Export — idle».

### Ось 8: терминология
- **F-17 MAJOR. Три словаря одновременно.** Таб называется «Servers», enum —
  `PROXIES`, проекция — `ProxyEntry`/`activeOutbound`, тексты — «Pick a server», поле
  ввода — «sing-box document», «outbound». Подписка называется и Subscription, и
  Route (карточка «Route» на Доме содержит сервер и подписку).
- **F-18 MAJOR. Локализации нет.** Все строки захардкожены в composable по-английски;
  `composeResources` отсутствует, `strings.xml` нет. В 1.x — 876 ключей в `app_en.arb`
  и `app_ru.arb`, включая правовые тексты. Для русскоязычного продукта это регресс
  относительно 1.x.

### Ось 9: согласованность с рантаймом
- **F-19 BLOCKER. Внутренняя модель рантайма протекает в основной UI.** Строка
  «Transport: starting, 0 lanes» (`HydraApp.kt:139`, собирается в
  `ScreenProjection.kt` из `transportHealth`) — ровно то, что запрещено. Место такой
  информации — Диагностика.
- **F-20 MINOR. При выборе «Авто» Дом показывает строку `auto`** (`AUTO_TAG`,
  `AppStore.kt:208`) вместо «Авто · <фактически выбранный сервер>»; какой сервер
  используется на самом деле, узнать негде.

### Ось 10: доступность
- **F-21 BLOCKER. Навигация без иконок** — `icon = {}` и в `NavigationBar`, и в
  `NavigationRail` (`AdaptiveScaffold.kt:52`, `:77`). Это одновременно нарушение MD3 и
  потеря цели нажатия.
- **F-22 MAJOR. Edge-to-edge нет** (`enableEdgeToEdge` не вызывается,
  `RuntimeControlActivity.kt:84`), инсеты не учитываются; на Android 15+ контент
  уходит под системные панели.
- **F-23 MAJOR. `TopAppBar` нет** — заголовок «HydraBox» это `Text` внутри
  прокручиваемой колонки (`AdaptiveScaffold.kt`), поэтому нет ни collapse, ни
  контейнера, ни места под действия экрана.
- **F-24 MAJOR. Нет contentDescription и объявления смены состояния;** состояние
  подключения передаётся только текстом внутри карточки, для screen reader смена
  состояния молчаливая.

### Брендинг
- **F-25 BLOCKER. Настоящая иконка HydraBox не перенесена.** В 2.0 нарисован
  собственный вектор «щит с галочкой» (`platform/android/src/androidMain/res/drawable/
  ic_hydra_logo.xml`, 2 пути) и залит цветом `#0E3B2A`. Реальные ассеты 1.x лежат в
  `HydraBox/hydrabox/android/app/src/main/res/mipmap-*/ic_launcher.png`,
  `drawable-nodpi/hydrabox_launcher_foreground.png`,
  `drawable-nodpi/hydrabox_launcher_monochrome.png`,
  `HydraBox/hydrabox/assets/branding/hydrabox-logo.png` — ни один не взят.

## 7. Функциональный разрыв под интерфейсом

Это главный вывод ревью, и он не про UI. Формальное закрытие карточек E скрыло, что
под интерфейсом нет части функциональности, о которой интерфейс должен говорить.
Редизайном одного UI Definition of Done не достигается.

- **G-01 BLOCKER. Генератор конфигурации — 150 строк против 2532 в 1.x**
  (`core/config/.../TunnelConfig.kt` против
  `HydraBox/hydrabox/lib/singbox/singbox_config_builder.dart`). В `route` всего два
  правила: `sniff` и `hijack-dns`. Нет `rule_set`, нет правил вообще. Следствие:
  «Правила» как раздел настроек нечем наполнить.
- **G-02 BLOCKER. `RouteData` — мёртвый код.** Тип объявлен и покрыт тестом, но не
  используется ни одним вызовом. Блокировка рекламы и РФ-маршруты в 2.0 не работают,
  хотя настройки под них частично есть в `Settings`.
- **G-03 MAJOR. Режимов маршрутизации нет.** В 1.x — отключено / только выбранные
  приложения через прокси / обход выбранными приложениями (`settings_routing_page`,
  2266 строк). В 2.0 есть только `exclude_package`/`include_package` в tun.
- **G-04 MAJOR. proxy-only (локальный прокси-порт без VPN) отсутствует** — в конфиге
  единственный inbound типа `tun`, mixed-inbound не генерируется.
- **G-05 MAJOR. Настройки, которые есть в модели, но не влияют ни на что:**
  `tlsFragmentationMode`, `urlTest*` (кроме url и интервала), `locationLookup*`,
  `memoryLimitEnabled`, `proxySort`, `notificationTrafficDisplayMode`,
  `russiaDnsDirectResolver`. Их нельзя показывать в UI, пока они не подключены.
- **G-06 MAJOR. Настроек темы и языка в модели нет вообще** — раздел «Внешний вид»
  требует расширения `Settings`.
